# ADR 0016：開店設定清單

- **狀態**：已採納
- **日期**：2026-11-03
- **決策者**：Sunkuo
- **前提**：[ADR 0013 自助申請試用](0013-trial-signup.md)、[ADR 0008 後台帳號與權限](0008-staff-permissions.md)

## 背景

形象頁開放自助申請後，新店家開通完就自己進後台，沒有人帶。原則是**不靠人工介紹**：需要人介入，就代表介面做得不夠好。新店家第一眼要知道「下一步做什麼」，而且不用看教學影片或跟著導覽點。

## 決策

儀表板最上方放一張「開店設定」清單，**依店家的實際資料自動打勾**，不靠店家手動勾選：

| 步驟 | 完成條件 |
|---|---|
| 確認店名、上傳 LOGO | 系統設定有自己的公司名稱（預設的「…管理系統」不算）且有 LOGO |
| 寫下付款方式 | `payment_instructions` 不是空白 |
| 新增教練／美容師 | 至少一位不是範例資料的教練 |
| 建立方案 | 至少一個上架中、不是用品、不是範例資料的方案 |
| 發布形象網站 | `websites.published` 有內容 |
| 迎接第一位會員 | 至少一位一般會員（不含綁定成教練的帳號、範例人員帳號）；附註冊網址可複製 |
| 串接 LINE 官方帳號（選做） | `line_oa_channels.is_enabled` |

- 範例資料（ADR 0013，`system_settings.sample_data`）不算數；店家清除範例資料後，被保留下來的（已有人使用的）就算店家自己的。
- 每一步都有一個按鈕直接到該做的頁面；第一個還沒完成的必做步驟用主要按鈕標出來。沒有該頁權限的帳號按鈕停用並提示。
- 全部必做完成後顯示「可以開始接受預約」；清單可以「隱藏」（整間店共用，`system_settings.onboarding_dismissed_at/by`），在系統設定可以重新顯示。
- 只給有「系統設定」權限的帳號看（主要管理者、管理者預設都有）。
- 判斷邏輯在後端 `services/onboarding.py`，API `GET /onboarding`、`POST /onboarding/dismiss|restore`；文字、連結由前端依行業用詞產生（`pages/admin/Dashboard/components/SetupChecklist.tsx`）。

### 完成送 10 天試用（2026-11-03 追加）

試用中的店家完成 6 項必做步驟，就多送 10 天試用，每家一次（R66）：

- 觸發：店家讀清單（`GET /onboarding`）時若必做全部完成，後端呼叫 `claim_setup_bonus()`。應用程式帳號對 `tenants` 只有讀取權限，所以延長由這個 SECURITY DEFINER 函式做；它只動目前租戶、狀態試用、有到期日、還沒到期、還沒送過（`tenants.setup_bonus_at`）的店家，天數固定寫在函式裡（應用程式不能指定），並寫一筆平台操作紀錄「開店設定完成，送試用天數」。
- 從原到期日往後加 10 天；送完清除租戶快取，頁首「試用剩 N 天」馬上更新，清單顯示「已多送你 10 天試用，試用到 …」並跳出恭喜訊息。
- 清單在完成前會提示「完成 6 項必做設定，再多送你 10 天試用」。已轉為正式（啟用）的店家不顯示、也不送。
- 之後清單再變成未完成（例如刪掉方案）不會收回；選做的 LINE 串接不影響。

不做的：導覽式教學（一步步高亮按鈕）與教學影片——多半被略過、功能一改就要重做。

- 常用頁面的空白狀態說明
