# ADR 0010：體驗券與折價券

- **狀態**：已採納
- **日期**：2026-10-30
- **決策者**：Sunkuo
- **前提**：[ADR 0005 健身房 LINE 官方帳號](0005-gym-line-oa.md)、[ADR 0008 後台帳號與權限](0008-staff-permissions.md)

## 背景

工作室想用體驗券吸引新會員上第一堂課，用折價券促進購買方案。系統的付款是「會員下單 → 轉帳 → 後台確認收款」，堂數由購買紀錄與堂數紀錄管理，預約、扣堂、退堂、出席、教練鐘點都建立在購買紀錄上。

## 決策

### 1. 一套優惠券，兩種用法

- **折價券**：購買方案時折抵金額（折固定金額或打折），可設最低消費與適用方案。
- **體驗券**：使用時換成一筆金額 0、已付款的購買紀錄，堂數照常入帳。

體驗券不另做一條預約路徑，預約、扣堂、退堂、簽到、教練鐘點都不用改。

### 2. 資料

- `coupons`（券的設定）：名稱、類型、說明、公開代碼（每家唯一，大寫英數）、折扣方式與數值（打折存折扣百分比，15＝85 折）、最低消費、適用方案、體驗券送的方案、是否計教練鐘點、LINE 新加入自動發、可使用期間、發出後幾天內有效、總張數、每人張數、新會員限定、啟用。
- `member_coupons`（會員手上的每一張）：狀態（可使用／已使用／已作廢；已過期依 `expires_on` 即時判斷，不存）、來源（輸入代碼／櫃台發放／LINE 加入／轉為會員）、發放者、到期日、使用時間、對應的購買紀錄、作廢原因。
- `purchases` 加 `original_amount`、`discount_amount`、`payout_excluded`；付款方式加「體驗券」。

都是租戶資料表（RLS）。券不刪除，只停用。

### 3. 發放管道

會員輸入公開代碼領取、後台發給指定會員（多選，不符合條件的略過並列出原因）、LINE 新加入會員時自動發（`issue_on_line_join` 的體驗券）、詢問轉為會員時選一張體驗券同時送。全部走 `services/coupons.issue()`，用同一套檢查，並鎖住券設定避免超發。

### 4. 折抵由伺服器計算

結帳畫面列出會員手上可用的折價券並預設帶入最划算的一張，也可以輸入公開代碼；金額一律由後端用 `quote()` 計算，下單時 `apply_to_purchase()` 在同一筆交易把券標成已使用。現在的付款是轉帳加後台確認，折價只是讓應付金額變少，收款流程不變。訂單取消時券退回。

### 5. 教練鐘點

建立體驗券時選擇是否計教練鐘點；不計時把購買紀錄標為 `payout_excluded`，鐘點結算略過用這筆堂數上的預約。

### 6. 權限

新增功能權限 `coupons`（優惠券，放在後台側欄「行銷」分類），預設加進「店長」範本。詢問轉為會員時送體驗券只需要「詢問名單」權限；後台登錄購買時套用券需要「購買紀錄」權限。

## 後果

- 第一期不做：用會員名單批次發券、發券時用 LINE 通知會員、使用統計與轉換率、多張券疊加、已付款訂單退款。
- 已付款訂單沒有退款流程，用了券的已付款訂單也沒有退券。
- 付款方式 enum 加了 `coupon`，PostgreSQL 無法在 downgrade 時移除這個值。
