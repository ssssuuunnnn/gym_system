# ADR 0006：會員名單與 LINE 受眾（行銷訊息）

- **狀態**：已採納
- **日期**：2026-10-28
- **決策者**：Sunkuo
- **前提**：[ADR 0005 健身房自己的 LINE 官方帳號](0005-gym-line-oa.md)

## 背景

健身房會定期整理「這段時間有來上課的會員」，再透過 LINE 發優惠或活動訊息，例如續約提醒、喚回很久沒來的會員、感謝忠實會員。「誰上過課」只有系統知道（出席紀錄），而編輯圖文訊息、優惠券、預約發送、開封與點擊報表，LINE 官方帳號後台都已經做得很好。

## 決策

### 1. 名單在系統篩，訊息在 LINE 官方帳號後台發

| 選項 | 結論 |
|---|---|
| **A. 系統篩名單 → 上傳成 LINE 受眾 → 健身房在 LINE 官方帳號後台用受眾群發** | **採用**：開發量小；用 LINE 原生的編輯器、排程、優惠券與成效報表 |
| B. 系統內編輯訊息並直接 multicast | 之後再考慮：要重做編輯器、排程與報表，功能反而比較少 |
| C. 只匯出 CSV | 保留為輔助：給沒綁 LINE 的會員打電話或傳簡訊 |

LINE 的受眾（audience）用 Messaging API 以使用者 ID 上傳，同一個官方帳號在 LINE 官方帳號後台可直接選用；以使用者 ID 建立的受眾沒有人數下限，一次請求最多 10,000 個 ID（超過時第一批 `POST /v2/bot/audienceGroup/upload` 建立、其餘 `PUT` 追加）。

### 2. 「上過課」的定義與篩選條件（R32）

已確認＋已出席的預約。條件：上課期間（最長一年）、團體課／私人課、教練（私人課看預約的教練、團體課看課程的教練）、期間出席次數下限、剩餘堂數上限（已付款課程方案加總）、最後一次上課距今天數。管理員與黑名單不列入。後台另有三個常用名單：續約提醒（近 3 個月、剩 ≤ 2 堂）、喚回老會員（近 6 個月有來、超過 30 天沒來）、忠實會員（近 3 個月 ≥ 8 次）。

### 3. 行銷同意另外取得（R31）

會員加入時同意的個資告知是「安排課程」，不包含行銷。依個資法，行銷要讓對方能拒絕、拒絕後停止，所以：

- `users.marketing_consent_at`：同意時間，NULL＝未同意；預設不同意。
- LINE 加入會員時有一個選填的勾選框；之後在「我的 › 優惠與活動訊息」開關（`PATCH /auth/line/preferences {marketing_consent}`）。
- 和服務通知（`users.line_notify`）分開：關掉優惠訊息不影響預約結果、上課提醒。
- 管理員在會員詳情只能看，不能代為同意。

### 4. 受眾只放可發送的會員（R33）

`POST /member-segments/audiences {name, filters}` 在伺服器重新篩一次，只上傳「已綁定 LINE 且同意優惠訊息」的會員；前端傳來的會員清單不被信任（前端也不傳）。系統只存 `line_audiences`（租戶表、RLS）：名稱、LINE 的 audienceGroupId、篩選條件、人數、建立者與時間，**不存 LINE 使用者 ID 名單**。封鎖官方帳號的人 LINE 會自動略過。

### 5. 費用透明

建立受眾不發訊息、不計費。群發時每送一人算一則、算在健身房自己的 LINE 方案；建立受眾的視窗顯示「約用掉 N 則」與本月剩餘額度（`GET /line-oa/quota`），額度不足時警告。

## API 與畫面

- `POST /member-segments/preview`（管理員）：名單與人數（可發送／未同意優惠訊息／未綁定 LINE）。
- `POST /member-segments/audiences`、`GET /member-segments/audiences`（管理員）。
- 後台側欄「會員名單」（`pages/admin/MemberSegments/`）：篩選卡（常用名單＋條件）、人數統計、名單表（可依 LINE 狀態切換）、匯出 CSV、建立 LINE 受眾視窗、已建立的受眾紀錄。
- 會員「我的」：優惠與活動訊息開關；LINE 加入會員表單：選填勾選框；會員詳情：顯示同意狀態。

## 之後

- 選項 B（系統內直接群發與排程）、受眾自動更新（例如每月自動重建「續約提醒」）。
- 優惠訊息目前只走 LINE，所以「我的」的開關在綁定 LINE 後才出現；若之後開放其他行銷管道（Email、簡訊），同意要再分管道。
