# ADR 0012：最新消息與會員標籤

- **狀態**：已採納（第一期）
- **日期**：2026-10-31
- **決策者**：Sunkuo
- **前提**：[ADR 0003 形象網站](0003-gym-website.md)、[ADR 0005 店家 LINE 官方帳號](0005-gym-line-oa.md)、[ADR 0006 會員名單](0006-member-segments.md)

## 背景

店家想在形象網站放公告（公休、活動、優惠），並把公告透過 LINE 傳給「某一群會員」。這群人有兩種來源：

1. 店家自己分的群，例如「VIP」「早鳥班」「產後媽媽」——需要在會員身上貼**標籤**，會員列表、會員名單也要能依標籤篩選。
2. 依上課紀錄篩出來的人（會員名單已有的條件：期間內上過課、教練、剩餘堂數、多久沒來）。

## 決策

### 1. 會員標籤

- `member_tags`（名稱每家唯一、顏色從 antd Tag 預設色挑）、`member_tag_links`（會員 ↔ 標籤，多對多）。都是租戶資料、RLS。
- 在會員詳情設定（跟著儲存列一起存，`PUT /users/{id}/tags` 整組取代）；在會員名單可把目前名單一次加上標籤（`POST /member-tags/{id}/members`）。
- 會員列表依標籤篩選（任一／全部），會員名單條件多一個「有任一個標籤」（`SegmentFilters.tag_ids`）。
- 標籤是店家內部的分類（可能是「難約」「敏感肌」這種字），**只在後台出現**：`UserOut.tag_ids` 只在 `/users` 填入，`/auth/me` 不帶。
- 權限：讀取給會員管理、會員名單、形象網站；修改給會員管理或會員名單。沒有另外新增權限代碼。

一開始想做「會員群組」（另一張表、在群組頁加會員），後來改成標籤：同一個概念同時解決「發公告給一群人」與「會員列表分類篩選」，不用維護兩套。

### 2. 最新消息

- `news_posts`：標題、摘要（列表與 LINE 卡片用）、內文（純文字，保留換行）、圖片（只能是本店上傳到 `/media/<子網域>/site/` 的檔案）、是否發布、第一次發布時間。
- 消息是獨立的資料，**不放在形象網站的草稿 JSON 裡**：發布／取消發布立即生效，不必再按「發布到網站」。網站內容只多一個段落 `news`（標題、首頁顯示幾則），舊網站自動補在「關於我們」後面。
- 網站：首頁「最新消息」段落（四種版型都有），`/site/news` 全部消息、`/site/news/<id>` 單篇（沿用首頁的頁首、頁尾與版型顏色；`NewsArticle` 結構化資料；放進 sitemap，robots 允許）。網址放在 `/site/` 底下，nginx 與 vite 已經轉給後端，不用改部署設定。預覽連結（`?token=`）看得到草稿。
- 權限：編輯消息＝形象網站；用 LINE 發送＝會員名單（R52）。

### 3. 用 LINE 發送

- 對象＝**勾選標籤的會員 ∪ 會員名單條件的會員**（不含管理員、黑名單）。
- 由店家自己的官方帳號推播（不是上傳受眾再到 LINE 後台發）：店家在一個畫面就能完成，看得到人數與額度。每位收件人算一則方案額度。
- 公告可能含促銷，屬於優惠與活動訊息：只發給已綁定 LINE **且同意優惠訊息**（R31）的會員，送出時再檢查一次；不看服務通知開關。
- 沿用會員推播的 outbox `line_member_messages`（新增事件「最新消息」）：重試、每月上限、發送紀錄、送完清掉內容都一樣。`dedupe_key = news:<消息>:<會員>`，同一則不會發給同一人兩次，所以「補發給新加標籤的人」直接再發一次就好。
- 發送前試算（`POST /news/{id}/broadcast/preview`）：找到幾位、這次會發幾位、未同意／未綁定／已收過各幾位，以及不能發的原因（LINE 官方帳號未啟用、消息或網站未發布、沒有可發送的人）。
- `news_broadcasts` 記錄每次發送的對象說明與人數，不存收件人名單；結果（成功／失敗／略過）從 outbox 統計。
- LINE 卡片：（https 時）大圖、店名、標題、摘要、「看完整內容」按鈕連到網站上的這則消息。

## 影響

- 會員推播多一種事件，`line_member._process` 對「最新消息」改看優惠訊息同意。
- `SegmentFilterCard`、會員名單工具（`lib/memberSegments.ts`）、網站圖片上傳（`SiteImageUploader`）改成共用元件。
- 規則 R50–R52（`docs/business-rules.md`），測試 `tests/test_news.py`。

## 之後可以做

- 排程發送、只發給某分店的會員。
- 消息分類、置頂、有效期限（過期自動下架）。
- 會員前台（LIFF）也有最新消息列表。
- 標籤的自動規則（例如滿 20 堂自動貼 VIP）。
