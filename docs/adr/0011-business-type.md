# ADR 0011：行業類型（健身／美體）與用詞

- **狀態**：已採納（第一期）
- **日期**：2026-10-30
- **決策者**：Sunkuo
- **前提**：[ADR 0001 多租戶](0001-multi-tenancy.md)、[ADR 0002 平台管理後台](0002-platform-console.md)

## 背景

系統原本只給健身房用，前後台到處是「教練、課程、堂、學員、簽到、體驗課」。現在也要給按摩、美容、SPA 等美體店用。功能大致相同（預約、方案、堂數／次數、服務人員），但用詞不同，而且美體店多半沒有團體課。

## 決策

### 1. 租戶加行業類型

`tenants.business_type`（`BusinessType` 健身／美體，存 `fitness`／`beauty`，既有資料為健身）。平台開通時選擇（`TenantForm`、`python -m app.cli create-tenant --type beauty`），之後平台可在健身房詳情修改（寫入操作紀錄、清除租戶快取）。`TenantInfo.business_type` 隨請求帶著，背景工作（LINE 通知、上課提醒）也一樣。

### 2. 一份名詞對照表，前後端各一份

`backend/app/services/terms.py` 的 `TERMS` 與 `frontend/src/lib/terms.ts` 的 `TERMS` 內容一致（測試會比對）。鍵包括 business、staff、service、private、group、unit、hours、attend、teach、customer、check_in、trial、book、staff_pay、商品分類與教練類型的顯示文字等。

| | 健身 | 美體 |
|---|---|---|
| 服務人員 | 教練 | 美容師 |
| 服務項目 | 課程 | 療程 |
| 一對一 | 私人課 | 個人療程 |
| 單位 | 堂 | 次 |
| 顧客 | 學員 | 顧客 |
| 報到 | 簽到 | 報到 |
| 體驗 | 體驗課 | 體驗療程 |
| 人員費用 | 教練鐘點 | 美容師服務費 |

前端用 `useTerms()`（讀不需登入的 `GET /tenant/profile`，快取 `['tenant-profile']`），後端用 `terms.t(key)`（依目前租戶）。店家不能自訂稱呼（決策時確認不需要）。

### 3. 只換顯示文字，API 的值不變

商品分類（團體課程／課程／用品）、教練類型（私人教練／團體課程教練／場租教練）、預約狀態等 API 值不改，程式判斷照舊；顯示時用 `productCategoryLabel`、`coachTypeLabel` 等轉換。

### 4. 團體課程功能開關

`system_settings.group_classes_setting`（None＝依行業預設：健身開、美體關），系統設定「功能」卡片可切換，立即生效。關閉時隱藏：後台「課程管理」選單、商品的團體課程分類與欄位、教練的「團體課程教練」類型與「授課」按鈕、會員預約頁的團體課分頁、購買方案的團體課程方案、形象網站的課表區塊。已建立的資料保留，權限與網址仍在（只是畫面不顯示）。

### 5. 防漏網

`tests/test_terms_guard.py` 掃描已改完的前端檔案，不允許直接寫「教練、學員、堂數、簽到、健身、上課、授課…」（API 字面值除外）；之後改完的畫面加進 `GUARDED`。

## 分期

- **第一期（本次）**：行業類型、名詞對照表、團體課程開關；會員與教練前台、後台選單與主要列表（儀表板、教練、預約審核、商品、購買紀錄、會員）、教練表單、LINE 通知卡片、後台鈴鐺、形象網站、權限名稱。
- **第二期**：其餘後台頁面（表單、設定說明、詳情頁）與後端錯誤訊息；美體版的 LINE 圖文選單圖片（目前圖片上寫「預約課程」）。
- **第三期**：依療程長度（60／90／120 分鐘）佔用預約時段；抽成式（依價格 %）的人員費用。

## 後果

- 新增畫面時一律用 `useTerms()`／`terms.t()`，不要直接寫健身用語。
- 已建立的公司名稱、網站內容是店家自己的資料，切換行業類型不會改寫（新網站、新設定才用美體的預設文字）。
