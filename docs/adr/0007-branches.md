# ADR 0007：分店

- **狀態**：已採納（第一期）
- **日期**：2026-10-29
- **決策者**：Sunkuo
- **前提**：[ADR 0001 多租戶](0001-multi-tenancy.md)

## 背景

有些工作室有好幾個營業地點。所有分店屬於同一家公司：網址、管理員與會員帳號、LINE 官方帳號、形象網站都共用，只是在建立課程、設定公休、預約時要分出是哪一間。

## 決策

### 1. 分店是公司（租戶）底下的一層資料，不是新的租戶

`branches`（租戶表、RLS）：名稱（同公司內不重複）、地址、電話、啟用、排序。網址、帳號、系統設定、LINE 都不分店。每家至少一間：既有資料在 migration 建立「總店」；新開通的健身房在第一次需要時由 `services/branches.default_branch` 自動建立「總店」。

### 2. 各資料和分店的關係

| 資料 | 關係 |
|---|---|
| 課程 `courses.branch_id` | 屬於一間分店（必填）；課程的教練要在該分店授課；已有預約的課程不能換分店 |
| 公休 `time_slots.branch_id` | **各分店獨立**；唯一鍵改成（公司, 分店, 日期, 時段） |
| 預約 `reservations.branch_id` | 團體課一律跟著課程；私人課由會員選（省略＝預設分店）。公休檢查只看這間分店 |
| 教練 `coach_branches` | 多選、至少一間；預約私人課時教練要在該分店授課 |
| 方案 `product_branches` | 沒有任何列＝全分店通用（預設）；只有「課程」分類可以限定分店，限定後只能在那些分店預約 |
| 會員 | 屬於公司，不屬於分店 |

新增課程、預約、公休、教練時沒指定分店，`db/session.py` 的 `before_flush` 會補上預設分店（排序最前面的啟用分店），所以只有一間店的工作室與既有程式都不用改。

### 3. 停用而不刪除

分店會被課程、預約引用，不能刪除只能停用。停用後不能新增該店的課程、預約與公休設定，既有資料保留；最後一間啟用分店不能停用；還有上架課程的分店要先下架才能停用。

### 4. 畫面

- 後台：側欄「分店管理」；公休設定先選分店；課程表單有「上課分店」，教練下拉只列在該店授課的團體課程教練；教練表單「授課分店」；商品表單（課程）「適用分店：全分店通用／只限指定分店」；課程列表、預約審核、會員名單可依分店篩選；課程、預約、教練、商品列表顯示分店。
- 會員前台：預約課程頁最上方切換分店（記住這台裝置上次的選擇）；團體課只列該店的課，私人課只列在該店授課的教練與該店開放的時段；自動選方案時略過不能在這間用的方案；確認面板、首頁、我的預約顯示分店。教練今日課表顯示分店。
- 分店選項一律顯示（只有一間時也顯示）。
- LINE 通知與形象網站課表：有兩間以上分店時才加上分店名稱。

## 之後（第二期）

- 分店店長權限：管理員可被限定只管理某幾間分店。分店過濾要加在每個查詢（RLS 只到公司層），等有連鎖客戶再做。
- 形象網站「分店資訊」段落（各店地址、地圖）、各店營業時間、依分店的報表與教練鐘點拆分。
