# CLAUDE.md

Fitness studio booking/management system: **FastAPI (Python) + PostgreSQL** backend, **React + TypeScript + Ant Design (Vite)** frontend, Docker Compose for local orchestration. **Multi-tenant SaaS** — many unrelated gyms share one deployment; see «Multi-tenancy» below and `docs/adr/0001-multi-tenancy.md`. All identifiers, UI copy, and comments in this repo are in **Traditional Chinese** — match that convention in new code.

## Commands

```bash
# Run the full stack (always prefer this over local dev servers)
docker compose up --build

# Frontend type-check + build — run after any TSX/TS change
cd frontend && npm run build

# Frontend lint
cd frontend && npm run lint   # if configured; check package.json scripts

# Backend tests (pytest on a real PostgreSQL `fitness_test` DB as the RLS-restricted app role; also run in CI)
cd backend && pip install -r requirements-dev.txt && python -m pytest -q

# DB migrations (inside backend/, local venv or `docker compose exec backend`)
alembic upgrade head
alembic revision --autogenerate -m "..."

# Platform CLI (owner connection) — day-to-day use the platform console at http://platform.localhost instead
python -m app.cli create-platform-admin --username ops --password ...
python -m app.cli create-tenant --subdomain alpha --name "Alpha 健身" --admin-username admin --admin-password ...
python -m app.cli list-tenants
python -m app.cli set-status --subdomain alpha --status suspended
```

Services once `docker compose up` is running: frontend `http://localhost`, backend docs `http://localhost:8000/docs`, PostgreSQL `localhost:5432`, adminer (DB browser UI) `http://localhost:8080` (server `postgres`, DB `fitness_studio`, owner `fitness_owner`/`changeme_owner`, app `fitness_app`/`changeme_app` unless overridden by `.env`; roles created by `docker/postgres/init-roles.sh` on first init). Each gym is `http://<subdomain>.localhost`; plain `http://localhost` uses `DEFAULT_TENANT` (compose default `demo`); the platform console is `http://platform.localhost`; a gym's `/` is its public website once published (else `/login`). `npm run dev` proxies `/api` + `/media` to `:8000` keeping `Host`, so the same works on `:5173`.

At container start the entrypoint runs migrations, provisions `DEFAULT_TENANT` (`python -m app.cli create-tenant`, idempotent), and seeds that gym's admin from `ADMIN_USERNAME`/`ADMIN_PASSWORD` (`backend/app/seed_admin.py --tenant`); the `/auth/register` endpoint always creates `role=member`.

## Multi-tenancy (ADR 0001)

- **Tenant = one gym (company)**, `tenants` table (`subdomain` unique, `status` 試用/啟用/停用 stored `trial`/`active`/`suspended`, `timezone`). Every other table inherits `TenantMixin` (`models/tenant.py`) → `tenant_id` FK. Per-gym uniqueness is composite: `(tenant_id, username)`, `(tenant_id, code)`, `(tenant_id, slot_date, start_hour)`, one `system_settings` row per tenant.
- **Isolation is enforced by PostgreSQL RLS**, not by router code: policy `tenant_isolation` on every business table, `tenant_id = NULLIF(current_setting('app.tenant_id', true), '')::int` for USING and WITH CHECK. DB roles: `fitness_owner` (owns tables; `MIGRATION_DATABASE_URL`, used by Alembic and `app.cli`), `fitness_app` (`DATABASE_URL`; NOSUPERUSER/NOBYPASSRLS, DML only, SELECT-only on `tenants`, nothing on platform tables) and `fitness_platform` (platform console, see below). No tenant set ⇒ every table looks empty.
- `db/session.py`: an `after_begin` Session event runs `set_config('app.tenant_id', session.info["tenant_id"], true)` per transaction; `before_flush` fills `tenant_id` on new rows. **Never filter by `tenant_id` or set it by hand in routers** — just use the injected `db`.
- `deps.py`: async `get_tenant` resolves `Host` → `<sub>.BASE_DOMAIN` (fallback `DEFAULT_TENANT`, else 404; 停用 → 403; 30 s TTL cache, `clear_tenant_cache()`), sets the `core/tenant_context.current_tenant` contextvar; `get_db` (import it from `app.deps`, not `app.db.session`) yields a tenant-bound session; JWTs carry `tid` and `get_current_user` rejects a token whose `tid` ≠ the host's tenant. Background/CLI code uses `db.session.tenant_session(tenant_id)`.
- Per-tenant: `clock.now_local()` uses `tenants.timezone` (fallback `STUDIO_TIMEZONE`); uploads go through `core/media.save_tenant_media(kind, data, ext)` → `MEDIA_DIR/<subdomain>/<kind>/<uuid>.ext`.
- **Adding a table**: inherit `(TenantMixin, Base)` and call `enable_tenant_rls("<table>")` (`app/db/rls.py`) in its migration after `create_table` (it also grants DML to `APP_DB_ROLE`). `tests/test_tenancy.py` fails if any table lacks either (platform-level tables go in `PLATFORM_TABLE_NAMES` instead). The Alembic history was squashed into `0001_baseline` (PostgreSQL); SQLite/MySQL are no longer supported.
- Accounts are per gym: the same person at two gyms has two unrelated accounts. Per-gym custom domains and billing are later phases (see the ADR); the platform console and gym website are below.

## Platform console (ADR 0002)

- Lives at `platform.<BASE_DOMAIN>` (`PLATFORM_SUBDOMAIN`, reserved — never a gym). Same frontend/API, split by host: `App.tsx` builds only one router (`isPlatformHost()` from `lib/host.ts` → `router/platform.tsx`, else `router/index.tsx`; both are `create…Router()` functions); `/api/v1/platform/*` (`routers/platform.py`) is router-gated by `deps.require_platform_host` → 404 on gym hosts, and the platform host is not a gym (gym APIs 404 there).
- Separate accounts: `platform_admins` (+ `platform_audit_logs`) — no `tenant_id`, no RLS, listed in `models/platform.PLATFORM_TABLE_NAMES`. Platform JWT (`create_platform_token`) carries `scope=platform` and no `tid`; `get_current_user` rejects any token with a `scope`, `get_current_platform_admin` requires it. Frontend keeps it in a separate store/client (`store/platformAuth.ts`, `api/platformClient.ts` + `api/platform.ts`).
- Third DB role `fitness_platform` (`PLATFORM_DATABASE_URL`, `deps.get_platform_db`): R/W `tenants`/`platform_admins`, R/insert `platform_audit_logs`, R/W `users` **under RLS** (switch with `db.session.act_as_tenant(db, tenant_id)` inside the transaction — only for managing that gym's admins), no grant on other business tables. Cross-tenant numbers only via the `SECURITY DEFINER` function `platform_tenant_stats(month_start)` (aggregates only). The app role has no access to platform tables.
- `services/tenants.py` is shared by the API and `app.cli`: subdomain rules (`subdomain_problem`, `RESERVED_SUBDOMAINS`), `create_tenant`, `create_tenant_admin`, `reset_tenant_admin_password` (admins only, never members/coaches), `audit()` + `AUDIT_ACTIONS`. Functions only flush — provisioning tenant + first admin + audit is one transaction. They also filter `tenant_id` explicitly because the CLI's owner connection bypasses RLS.
- Endpoints: `POST /platform/auth/login` (JSON), `GET /auth/me`, `POST /auth/change-password`; `GET/POST /platform/tenants`, `GET /tenants/check-subdomain`, `GET/PUT /tenants/{id}` (subdomain immutable), `POST /tenants/{id}/status` `{status, reason}`, `GET/POST /tenants/{id}/admins`, `POST /tenants/{id}/admins/{uid}/reset-password`, `GET /platform/audit-logs?tenant_id&limit`. Every state change writes an audit row (no passwords).
- UI (`pages/platform/`): `Login`, `TenantList` (summary stats, search, status `Segmented`), `TenantForm` (開通: live subdomain check, timezone, contact, first admin + generated password; shows credentials once via the shared `components/credentials.tsx`), `TenantDetail/` (info card with dirty-diff save, status card with 停用 reason modal + usage stats, admins card, audit log), `AuditLogs`, `Account`. Shared `components/platform/AuditLogTable.tsx`. `StatusTag` colours 試用/啟用/停用.
- First platform admin: `PLATFORM_ADMIN_USERNAME`/`PASSWORD` at container start, or `python -m app.cli create-platform-admin`.
- Tenant-host cache: hits 30 s, misses 5 s, and creating a gym clears the local cache.

## Gym website (ADR 0003)

- Each gym's **home page `/` is its public website**, server-rendered by FastAPI + Jinja2 (`routers/site.py`, `templates/site/bold.html`, `static/site/site.css` mounted at `/site/static`) — no JavaScript (menus/FAQ are `<details>`, the trial form is a plain POST → 303). Unpublished ⇒ `/` redirects to `/login`. `frontend/nginx.conf` and `vite.config.ts` send `/` (except on the platform host), `/site/*`, `/robots.txt`, `/sitemap.xml` to the backend with `Host: $http_host`; everything else stays SPA.
- Content: one `websites` row per tenant with `draft` and `published` JSON, shape/validation in `schemas/website.py` `SiteContent` (sections hero/about/schedule/coaches/pricing/gallery/faq/trial/contact, order + visibility; hero/about/contact required; empty sections auto-hide). Coaches/products are stored as ids + website copy only — names, photos, prices and sessions are read live; the class list comes from `services/schedule.group_sessions` (shared with `GET /courses/schedule`). One theme (`bold`); `brand_color` limited to the 5 contrast-checked `BRAND_COLORS`.
- **Public-field whitelist** (R16): `_coaches`/`_plans` in `routers/site.py` pass only alias/name, specialty, photo, website bio, product name/category/hours/price to the template. Never hand ORM objects to the template. Links validated in the schema (LINE `@id`/lin.ee/line.me, Instagram username, https facebook.com); images must be `/media/<own subdomain>/site/<uuid>.jpg|png` (checked on save and publish).
- Admin API `routers/website.py` (admin-only): `GET /website`, `PUT /website/draft`, `POST /website/publish|unpublish|discard-draft|preview-token|upload-image` (jpg/png ≤ 5MB). Preview: `/site/preview?token=` with a 30-min `scope=site_preview` JWT (`create_site_preview_token`; can't call APIs).
- Trial enquiries: `POST /site/inquiry` (honeypot field `website`, ≤3 per IP-hash per 10 min, consent required) → `inquiries` (+ `inquiry_notes`), statuses 新詢問/聯絡中/已約體驗/已成為會員/未成交 (stored `new`/`contacting`/`trial_booked`/`converted`/`lost`). `routers/inquiries.py` (admin): list (+ lazy purge of non-converted enquiries older than 183 days, R18), `/summary` (sidebar badge), `PATCH` status (not 已成為會員), `POST /{id}/notes` (first note moves 新詢問→聯絡中), `POST /{id}/convert` (creates a member, `must_change_password` default true).
- UI: admin sidebar **形象網站** (`pages/admin/Website/`: `SectionNav` + one panel per section in `components/panels/` + `PreviewPane` iframe + sticky 捨棄草稿/儲存草稿/發布到網站 bar; panel labels are linked via `htmlFor`/`id`) and **詢問名單** (`pages/admin/Inquiries.tsx`, drawer with status/notes/convert, badge with new count). `components/credentials.tsx` (`showCredentials`, takes a `loginUrl`) is shared with the platform console. Rules R16–R19 in `docs/business-rules.md`.

## LINE store notifications (ADR 0004)

- One **shared platform LINE Official Account** (Messaging API; LINE Notify is gone). Secrets only in env: `LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_BOT_BASIC_ID` (+ `LINE_BOT_NAME`, `LINE_PLAN_MONTHLY_QUOTA`, `PUBLIC_SCHEME` for card links, `LINE_DISPATCH_INTERVAL_SECONDS`). All three unset ⇒ `services/line.get_client()` is None ⇒ notifications are recorded 未設定 LINE and the UI shows a warning. Never put secrets in the DB or UI.
- Tables: `line_recipients` (`line_user_id`, `display_name`, `notify_inquiry`/`notify_payment`/`notify_booking`, `is_active`, `bound_by_name`), `line_bind_codes` (sha256 `code_hash` only, 10 min, single use), `line_notifications` (outbox: `recipient_ids`/`message` JSON cleared once finished, `status` 待發送/重試中/成功/失敗/超過上限/未設定 LINE stored `pending`/`retrying`/`sent`/`failed`/`skipped_cap`/`skipped_disabled`, `attempts`, `next_attempt_at`, `note`) — all tenant/RLS; platform table `line_bind_attempts` (rate limit 5 failures / 10 min per LINE user). `tenants.line_monthly_cap` (default 300, edited via `PUT /platform/tenants/{id}`, audited).
- Events (`services/line.notify_inquiry|notify_payment|notify_booking`, each with `enqueue` in the request's transaction, then `line.schedule(background_tasks, id)` after commit): `site.submit_inquiry`, `purchases.create_self_purchase`, `reservations.create_reservation` **only when member-submitted**. Cards are minimal (R22): surname only via `masked_name` (王先生／小姐), **never phone/email/notes**; button links to `{PUBLIC_SCHEME}://{sub}.{BASE_DOMAIN}/admin/...`.
- Dispatch (`dispatch_tenant`/`dispatch_all_due`, background thread from `main.lifespan`): claims rows `FOR UPDATE SKIP LOCKED`, monthly cap counted from the tenant-local month start (skips ⇒ 超過上限), multicast ≤500, retryable errors (no status/429/5xx) retry at 1/5/30 min then 失敗.
- Admin API `routers/line.py` (admin-only, `/line`): `GET /settings`, `POST /bind-codes`, `GET /bind-codes/{id}` (poll: waiting/bound/expired), `PATCH|DELETE /recipients/{id}` (delete = deactivate), `POST /recipients/{id}/test`. Webhook `routers/line_webhook.py` `POST /api/v1/line/webhook` — **platform host only**, verifies `x-line-signature`, uses `get_platform_db`; follow → welcome reply, unfollow → `line_deactivate_user`, 6-digit text → `line_consume_bind_code` (SECURITY DEFINER, binds only if exactly one active code matches) then `act_as_tenant` to create/reactivate the recipient. Platform: `GET /platform/line/summary?month=` and `GET /platform/line/logs?status&limit` via SECURITY DEFINER `platform_line_usage` / `platform_line_log` (aggregates + results only, no recipients or content). The app role can't execute any of these functions.
- UI: 系統設定 (`pages/admin/SystemSettings/`, now a folder) → `components/LineNotifyCard.tsx` (usage bar, recipients table with the 3 event checkboxes, 傳送測試通知, 移除) + `LineBindModal.tsx` (antd `QRCode` of the add-friend URL, code + countdown, polls every 3 s); actions apply immediately, outside the sticky save bar. Platform sidebar **LINE 通知** (`pages/platform/LineNotifications.tsx`: month picker, stats vs plan quota, per-gym table with inline cap `InputNumber`, log with `Segmented` filter). `api/line.ts`, platform additions in `api/platform.ts`. Rules R20–R23 in `docs/business-rules.md`. Tests `tests/test_line.py` patch `get_client`/`schedule` via the `fake_line` fixture.

- Each gym connects **its own** LINE OA (unlike ADR 0004's shared platform OA for staff). ## Architecture

```
backend/app/
  models/     SQLAlchemy ORM models (1 file per table)
  schemas/    Pydantic request/response models (1 file per resource)
  routers/    FastAPI route handlers (1 file per resource)
  core/       config.py (env-driven Settings), security.py (JWT + bcrypt)
  deps.py     shared FastAPI dependencies (auth/role guards)
  db/session.py  SQLAlchemy engine/session, declarative Base
  alembic/    migrations (autogenerate-driven)

frontend/src/
  api/        one file per resource, thin axios wrappers returning typed data
  pages/admin/    admin-only screens (後台, AppLayout)
  pages/member/   member front-end screens (前台, MemberLayout mode="member")
  pages/coach/    coach front-end screens (前台, MemberLayout mode="coach")
  pages/common/   Login, Register
  components/     shared UI: AppLayout (admin sidebar+header), SlotPicker (week grid), StatusTag; calendar/ (排程原子組件); member/ (前台 shell + building blocks)
  store/auth.ts   zustand store, persisted to localStorage (login survives refresh)
  router/index.tsx   route table; RequireRole.tsx guards by role
```

Every backend resource follows the same triad: `models/X.py` (table) → `schemas/X.py` (`XCreate` / `XUpdate` / `XOut`) → `routers/X.py` (registered in `main.py` under `API_V1_PREFIX` = `/api/v1`). Follow this triad for any new resource.

## Data model (21 business tables + `tenants` + platform tables)

`users` (admin/member, `is_coach` is a **derived** value — true iff a `coaches` row references the user, not a stored column; `is_blacklisted` and `must_change_password` are stored flags the admin sets from 會員詳情) · `coaches` (`user_id` bind is unique; plus `name`, `alias` 授課名稱, `line_name`, `phone`, `bank_code`/`bank_account` 匯款帳號, `specialty` 專長, `photo_url`, `session_rate` 私人課每堂鐘點費 (default 0), coach types as booleans `is_private_coach` (default true) / `is_group_coach` / `is_rental_coach` exposed in the API as `coach_types: ['私人教練'|'團體課程教練'|'場租教練']` (multi-select, at least one, 場租 can't combine with the others — `schemas/coach.py` `_validate_types`); `GET /coaches/me` (`require_coach`) returns the caller's own coach row; **`GET /coaches` blanks `phone`/`line_name`/`bank_code`/`bank_account`/`session_rate` for non-admins** — never expose these to members) · `products` (catalog, three kinds via `category` enum — stored `course`/`single_course`/`supply`, API 團體課程/課程/用品: **團體課程** binds `course_id` → a `courses` row and `session_hours` mirrors that course's `session_count` (set server-side, read-only in the form, `stock` null); **課程** (單次課程) has an admin-entered `session_hours` (≥1), `course_id`/`stock` null; **用品** carries `stock` (decremented on purchase; `create_purchase` 400 「庫存不足」 when short), `session_hours` 0, `course_id` null; plus `price`, `is_active`) · `purchases` (a member's purchased session-hours; `total_hours` = 下單當下 `session_hours * quantity`, `remaining_hours` = current balance (only via `services/hours.py`); **付款狀態** `payment_status` 待付款/已付款/已取消 (stored `unpaid`/`paid`/`cancelled`) + `payment_method` 現金/轉帳/刷卡/其他 (stored `cash`/`transfer`/`card`/`other`), `payment_note`, `paid_at`, `paid_confirmed_by`, `cancelled_at`; for a 用品 purchase `total_hours`/`remaining_hours` are 0 and `products.stock` is decremented at order time) · `hour_ledger` (堂數異動紀錄: one row per change to `purchases.remaining_hours` — `delta` (+增/−扣), `balance_after`, `reason` 期初餘額/購買/預約扣抵/預約退回/手動調整 (stored `opening`/`purchase`/`reservation_deduct`/`reservation_refund`/`manual_adjust`), optional `reservation_id`, `note`, `created_by`; invariant `SUM(delta) == remaining_hours`) · `time_slots` (per-date slot-availability exception: `slot_date` + `start_hour` 10–21 + `is_open`, unique per date+hour; **no row for a date/hour = open by default**) · `system_settings` (one config row per tenant: `company_name` / `short_name` / `logo_url` / `cancel_deadline_hours` 取消期限 (default 12, 0＝不限制); lazily get-or-created — see 系統設定 below) · `courses` (團體課程 bound to a coach: auto `code` `GC-YYYY-NNN`, `status` 上架/下架/草稿, `min_capacity` 最低開班, `max_capacity` = **每堂**容量, `coach_fee` 每堂教練費 (團體課程教練鐘點用, default 0; `null` for non-admins in `GET /courses` and `GET /courses/{id}`; create/changing `coach_id` requires an `is_group_coach` coach — 400 「團體課程只能指定團體課程教練」, re-saving an existing course with its current coach is allowed), `duration_minutes` (**one value per course**), `description`, `cover_image_url`, `updated_by_name`, `is_archived`/`archived_at`/`archived_by_name`; **排程規格 lives on the course row** — `start_hour` (單一上課時間), `start_date`, `end_mode` 週數/結束日, `week_count` / `end_date`; `day_of_week` = the **min weekday** (denormalised for the list summary), all nullable for a 草稿; `session_count` = non-cancelled `course_sessions`; `start_date`/`end_date` = the schedule spec (`end_date` is the input in 結束日 mode, or `start_date` + `week_count` in 週數 mode); `enrolled_count` (API only) = **peak single-session** headcount from `reservations`) · `course_weekdays` (course_id, `weekday` ISO 1–7; the 多選 上課星期) · `course_sessions` (the展開後 課堂 list: `session_date`, `start_minute`, `duration_minutes`, `source` 排程/加開, `is_cancelled` 停課 (kept as a record, not counted); FK `ON DELETE CASCADE`) · `reservations` (status: 待確認/已確認/已拒絕/已取消; source: member_submitted/admin_created; `late_cancel` 晚取消 flag; `attendance` 已出席/未到 (stored `attended`/`no_show`, NULL＝未簽到) + `checked_in_at`/`checked_in_by`) · `coach_payouts` (教練月結 snapshot: `coach_id` + `period` (該月 1 日, unique together), `session_count`, `rate`, `amount`, `status` 已結算/已撥款 (stored `settled`/`paid`), `settled_at/by`, `paid_at/by`, `payment_note`) · `coach_payout_items` (snapshot rows: `kind` 私人課/團體課 (stored `private`/`group`), `course_id`, `title`, `session_date`, `start_hour`, `fee` 該堂教練費, `attended_count`, `no_show_count`, `members`; FK `ON DELETE CASCADE`) · `websites` / `inquiries` / `inquiry_notes` (gym website, see «Gym website») · `line_recipients` / `line_bind_codes` / `line_notifications` (LINE store notifications, see «LINE store notifications») · `line_oa_channels` (the gym's own LINE OA, see «Gym LINE Official Account»; **Reservation capacity** (`routers/reservations.py` `_check_capacity`): a reservation whose product/`course_id` resolves to a `courses` row is capped by that course's `max_capacity` (每堂容量) — `SUM(people_count)` of 已確認 reservations with the same `course_id` + `booking_date` + `start_hour`; no course link ⇒ no cap. (Replaced the old per-`category` `CAPACITY_BY_CATEGORY` map.)

**Enum columns store the Python enum *member name*, not the Chinese `.value`** (SQLAlchemy default): e.g. `courses.status` is stored as `on`/`off`/`draft`, `products.category` as `course`/`single_course`/`supply`, `reservations.status` as `pending`/`confirmed`/… — the API layer (Pydantic `XOut`) serializes back to the Chinese value. Alembic `sa.Enum(...)` declarations, raw SQL, and seed inserts must use the names.

**`day_of_week` is ISO-8601: `1` = 週一 … `7` = 週日** — used by `courses` (`day_of_week` = 最小上課星期; the full 多選 lives in `course_weekdays.weekday`). `time_slots` keys off a concrete `slot_date` instead. Frontend labels come from `frontend/src/lib/weekday.ts` (`weekdayLabel` / `WEEKDAY_SHORT_MON_FIRST`) — don't re-declare weekday arrays per file.

## Auth & permission model

JWT bearer tokens (`app/core/security.py`, payload `sub`/`tid`/`role`/`is_coach`), role = `admin` | `member` — `admin` is that gym's admin only. Key dependencies in `deps.py`:
- `get_current_user` — any authenticated, non-blacklisted user
- `require_admin` — admin only
- `require_coach` — member with a bound `coaches` row

**Established pattern for list/read endpoints that both admins and members need** (see `routers/purchases.py`, `reservations.py`, `coaches.py`, `products.py`, `courses.py`): the route itself only requires `get_current_user`; inside the handler, non-admins are **silently scoped to their own data** (e.g. `purchases`/`reservations` force-filter by `current_user.id`, ignoring any different id passed in). Mutations (`POST`/`PUT`/`DELETE`) stay `require_admin`-gated per-route. Follow this pattern rather than gating an entire router with a single `dependencies=[Depends(require_admin)]` — several routers used to do that and it silently broke member-facing pages that needed read access to catalog data (coaches/products/courses) or their own purchases/reservations.

`time_slots` is the single source of truth for slot availability — read by the settings screen, the reservation-review screens, and reservation creation (both member submit and admin create) alike.

**File uploads**: `POST /coaches/upload-photo` (multipart, admin-only, jpg/png ≤ 2MB) saves via `save_tenant_media` under `settings.MEDIA_DIR/<subdomain>/` (`/app/media`, a named volume `coach_media`) and returns a `/media/...` URL; `main.py` mounts that dir as StaticFiles at `/media`, and `frontend/nginx.conf` proxies `/media/` to the backend. Store the returned URL in `coaches.photo_url`. This is the pattern for any future upload.

**Forced password change**: when an admin resets a member's password from 會員詳情 with "會員下次登入時必須自行修改密碼" ticked, `POST /users/{id}/reset-password` sets `users.must_change_password`. `/auth/login` returns that flag in the token response; the frontend stores it and `AppLayout` redirects to `/member/change-password` (rendered outside `AppLayout`) until the member calls `POST /auth/change-password` (verifies current password, clears the flag). Enforcement is frontend-only — the API token still works elsewhere.

## Frontend conventions

Every list page follows the same shape (see `pages/admin/CoachList.tsx`, `BookingReviewList.tsx`, `MemberList.tsx` as references):
- `useQuery` (TanStack Query) for data fetching, keyed by resource name
- Antd `Table` with typed `ColumnsType<T>`
- Name/label lookups for foreign keys done client-side via `Map` built from a sibling `useQuery` (e.g. `coachNameById`), since API responses return raw ids
- Mutations via `useMutation` + `queryClient.invalidateQueries` on success, `message.success/error` for feedback
- `Popconfirm` for destructive/state-changing actions (approve/reject/cancel)

`api/*.ts` files are thin: exported TS interfaces mirroring the backend `XOut` schema, plus one async function per endpoint using the shared `apiClient` (axios instance in `api/client.ts` with JWT-injecting request interceptor and 401→logout response interceptor).

`components/SlotPicker.tsx` is the canonical week grid — a dated 7-day time grid (`dates: Dayjs[]` × 10:00–21:00) composed from the `components/calendar/` atoms (`TimeAxis`, `DayHeaderCell`, `TimeSlotCell`, `NowIndicator`, `EventBlock`); `SlotState` = `open | closed`. Optional `cellEvents(date, hour) => SlotEvent[]` prop overlays `EventBlock`s (side-by-side via `colIndex`/`colCount`; a `SlotEvent` without `onClick` gets `pointerEvents:none` so the cell stays clickable, one with `onClick` is itself clickable) — `SlotSettings` uses it to show existing reservations on closed cells (not courses). Optional `cellDisabled(date, hour) => boolean` greys out + blocks extra cells beyond the always-disabled past dates (`CourseForm` passes it for 公休 slots on its read-only preview). `SlotSettings` owns the week nav + `MiniCalendar` + legend layout. Extend `SlotPicker`/`TimeSlotCell` rather than building a parallel grid component.

`components/InlineRuleList.tsx` (`InlineRuleList` + `InlineRuleRow`) is the shared chrome for a **numbered setting-row list** — a soft panel with title/description, rows each carrying a `規則 N` / `設定 N` chip (`chipPrefix` via context) and a trailing delete button, plus a dashed 新增一列 button (`readOnly` hides the add + per-row delete buttons). Row *contents* stay with the caller. Used by `Availability`'s 快速設定 (批次關閉); reuse it for any future batch-rule editor rather than re-styling a panel.

`components/courseColumns.tsx` (`sharedCourseColumns({ coachNameById })`) + `components/CourseCoverThumb.tsx` are the 7 course-row columns (封面 / 課程名稱 / 教練 / 開班人數 / 課程介紹 / 課堂數 / 開課時間) shared by `GroupCourseList` and `GroupCourseArchive`; each page spreads them then appends its own columns (狀態＋操作 / 封存資訊＋還原刪除).

`components/calendar/` holds 8 presentational scheduling atoms imported from the PulseFit design system (`TimeAxis`, `TimeSlotCell`, `DayHeaderCell`, `EventBlock`, `EventChip`, `NowIndicator`, `MonthDayCell`, `MiniCalendar`) — colours/radius/font via `theme.useToken()`, no global CSS. See `components/calendar/README.md`.

When **authoring or reviewing a UI component** (not a page screen), follow the `component-conventions` skill: where it lives (shared `frontend/src/components/` for 2+ consumers vs. page-scoped `frontend/src/pages/<Area>/<Page>/components/` for a single consumer), reach for an Ant Design component before hand-rolling, colours/radius via `theme.useToken()` (no hardcoded hex), `dayjs` for all date work, one shared source for constants/helpers, controlled props-driven components, and "one concept, one component". The layout shells (`BackOfficeShell.tsx` shared by `AppLayout.tsx` and `platform/PlatformLayout.tsx`; `member/MemberLayout.tsx`) have their own `layout-conventions` skill.

Shared front-end lookups: `lib/useBookingLookups.ts`; time helpers in `lib/booking.ts` (`classEnd`, `selfCheckInOpensAt`, `relativeStartLabel`). Use `App.useApp().message` in new pages (not the static `message`).

**Server timestamps are naive UTC** (`datetime.utcnow()`): always display them with `formatServerTime()` from `frontend/src/lib/datetime.ts` (dayjs utc → local), never `dayjs(value).format(...)` directly — that shows UTC as local time (8 hours off in Taipei).
